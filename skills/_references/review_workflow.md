# 国赛个人工作流：审核与逐问推进

本文件由六个阶段共同读取，规定本套个人版的审核和交接。模型选型知识仍按需读取 `math_modeling_norms.md`。默认用于全国大学生数学建模竞赛、中文论文；用户指定其他场景时沿用其要求。

## 审核顺序

```text
题意、数据初查及整体路线 → 整体路线审核
  ↓ 通过
当前问详细方案（稳健路线与探索选项） → 方案审核
  ↓ 通过
稳健方案实现、验证、图表初稿 → 基线结果审核
  ↓ 通过
如有已批准且仍适用的探索：有限实验与可比验证 → 最终结果审核
  ↓ 通过（未探索时，基线结果审核即本问最终结果审核）
积累本问论文段落 → 更新后续依赖 → 下一问
  ↓ 全部完成
全文整合 → 最终验收
```

每次只实施当前问。整体路线通过不等于逐问方案通过，方案通过不等于结果通过。不得用多问批量编码、后台任务或单独调用下游 Skill 绕过审核。用户仅要求讨论、单阶段或检查时保持请求范围；必要审核仍适用于该范围内的求解与结果采纳。

阶段产物按任务适配：统计/描述题不强填优化目标，解释/建议题可直接形成有依据的建议结果，无需虚构公式、代码或图表。它们仍经过本问方案及结果审核，通过后积累章节。

## 什么算审核通过

向用户展示具体、可评估的材料，标明本次审核对象与版本，给出结果文件或报告位置，并说明下一步。用宿主可用的提问方式请求决策，不依赖特定名称的工具。

只有用户针对该对象的明确接受、选择或执行指令才记为通过。已有会话中清晰对应的批准应复用，不重复确认；没有回复、等待超时、泛泛的“继续”和对其他问题的回复不能猜成批准。指向当前唯一审核项的“通过，继续”可以接受。多项待审且回复含糊时只澄清具体对象。

用户要求修改则返回对应阶段，形成新版本再提交；只批准某条路线或部分结果时不得扩大范围。审核材料提交后暂停依赖该决定的工作，交还用户，不自行填入“用户已确认”。可继续不受待审决定影响的资料整理，不提前实施下一问。

## 三类审核材料

| 审核 | 应提供的内容 |
|---|---|
| 整体路线 | 题意与各问关系、数据现状、共享假设及重要歧义、相关研究及方法适用条件、各问拟用方向、输入输出依赖、主要风险 |
| 本问方案 | 使用的已批准前问结果版本；问题抽象、数学模型、求解算法与验证方法；候选的适用依据、假设/遗漏机制、选用和排除理由、放弃标准；文献与本题差异、证据缺口、成本和探索范围 |
| 本问结果 | 实际方法及偏差、关键数值与来源、约束/误差/基线检查、图表初稿、异常与局限、对后问的具体影响、建议采用结果版本 |

不必在整体路线阶段提前敲定每问全部公式。允许为分析歧义做小规模探索验算，但必须标为探索且限定用途，不冒充最终结果或借此开始未批准的大规模求解。

文献检索与核实按 [文献参与建模规则](literature_support.md) 执行，记录在 `reports/LITERATURE_REPORT.md`，随现有整体/逐问方案审核，不单独审批。明确区分题面给定、外部证据与自拟假设；用户接受证据缺口不等于该引用已核实。新文献若推翻已批准模型的关键前提，按下述变更规则处理。

## 稳健与探索

- 每问先给成熟、可实现、可验证的稳健方案；有实质改进空间时同时给探索选项，说明题目依据、预期收益、风险、额外假设及运行成本。简单问题不为凑数量虚构复杂模型。
- 稳健方案可以是依据明确的自拟模型，不要求属于知识库清单或有固定名称。候选清单不完整，清单内外按同一标准审核；不得强制提出清单外方法，也不强制凑两条路线。探索须针对基线的具体不足，不仅是替换算法名称。
- 由用户决定探索是否开展及投入边界。方案批准时未包含探索授权，只执行稳健方案；授权范围未清楚时，在开展探索前澄清。
- 先运行稳健方案并审核基线结果。基线通过后，已批准且方向仍适用的探索自动开展，无需再次询问同一授权；否则提交改动方案。
- 按同一数据划分、约束与评价口径比较，报告差异和不确定性。若改动了比较口径，应重新得到许可并重建公平比较。
- 达到约定时间、实验数量或停止条件时停止探索。未取得可信提升就保留基线，最终采用方案由用户审核，不能自动选择最复杂或看似最优的模型。
- 若基线本身不满足关键约束或有效性标准，不能因探索失败就采纳无效基线。说明缺口、影响范围与候选扩展方向，回到方案审核；合理预算内仍无法解决时明确未解决部分，不声称已找到最佳模型。

## 最小审核记录与恢复

跨问交接、进入各阶段及上下文压缩/中断后恢复时，读取并执行 [跨问记录与上下文恢复](context_memory.md)。助手维护赛题工作区的 `reports/STATE.md` 和 `reports/models/qN.md`，重新读取相关前问的批准模型与源结果；保存和核对并入原有审核，不新增审批。

在 `reports/REVIEW_LOG.md` 保存审核记录，`plan.md` 保存当前整体路线与偏好，`todo.md` 保存当前问和下一步。报告由模型按真实会话填写；这些文件是记录而非强制执行程序，不会代替用户作决定。

审核记录每项包含：

- 对象标识：如 `route-v1`、`q1-plan-v1`、`q1-baseline-v1`、`q1-result-v2`。
- 材料位置、使用的数据/模型/前问结果版本及简要内容。
- 状态：`PENDING`（待审）、`APPROVED`（通过）、`REVISION_REQUESTED`（需修改）、`STALE`（受变化影响失效）。
- 用户决定的原意或简短原话、对应会话轮次或时间、批准范围、后续动作。

复用当前已批准版本时不要重复审核。恢复任务先读记录并与现有文件和会话核对；材料变了或批准证据不明时不能靠文件名猜测批准。重新批准新版本时保留旧记录，标明其已被替代。

## 哪些变化需要重新审核

修复不改变数值含义的实现错误、在已批准范围内调参、优化计算效率可自动进行。改动关键假设、模型路线、目标函数、约束、评价口径、数据清洗/划分原则或扩大探索投入，需要先提交原因、拟改内容与影响范围，得到审核后实施。

任何导致已批准数值或结论改变的修复，即使代码修复本身无需许可，新结果仍需审核。先列出受影响的后问输入、方案、结果、图表与论文段落，将相应批准标为 `STALE`，暂停使用这些材料；不影响的成果继续保留。整体依赖或共享假设改变时返回整体路线审核，仅局部改变时重审局部。

## 图表与写作交接

图表先生成，与结果一起提交，不另设绘图前置审核。按 [个人绘图规范](figure_style.md) 区分本图修改和通用风格。用户明确接受数值、只要求外观微调时记录结果批准与待改图项，按其要求继续；会改变数据解释、展示尺度或结论的修改需重新确认相关结果。

仅在本问最终结果通过后，`5writing` 积累本问方法和结果段落。若已批准探索仍未完成，该问尚未最终定稿。章节积累不增设强制审核，但发现科学含义或证据缺口时返回对应审核点。前问变更时同步修订受影响草稿。全文整合和最终验收不能跳过未审核或失效的必需结果。
