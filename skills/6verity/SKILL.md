# 验证和验收（Typst / LaTeX）

本 skill 是完整工作流的最后一关。它不重新建模、不生成新结果、不代替写作阶段重写论文；它负责发现硬错误、修复可直接修复的问题，并输出 `reports/VERIFY_REPORT.md`。

先读取 [审核与逐问推进规则](../_references/review_workflow.md)。用户只要求阶段检查时按该范围执行；最终验收还须核对 `REVIEW_LOG.md` 中整体路线、各问方案和最终结果有效，通过 `PAPER_NOTES.md` 检查跨问依赖及论文版本。技术校验通过不能替代用户结果审核。

按 [跨问记录与上下文恢复](../_references/context_memory.md) 检查状态索引、模型记录与源材料一致，核对实际跨问依赖的版本、单位、假设及适用限制，并排查失效版本引用。只有第一问或尚无跨问依赖时如实标为不适用；存在依赖却未核对则标为未检查，不能因记录文件齐全宣布恢复可靠。

## 数学建模规范参考

如需领域判断，读取 `../_references/math_modeling_norms.md` 中的"论文验收与一致性"小节。该文件只是规范知识库，不是固定执行流程；具体目录、入口文件、结果文件和图表目录由当前项目结构决定。

## 阶段边界

- 本阶段负责：结构验收、文本质量门禁、图表引用检查、结果一致性检查、Typst/LaTeX 编译检查、PDF 视觉检查、提交清单。
- 本阶段不负责：重新设计模型、重新跑大规模实验、重新组织整篇论文。
- 发现硬错误时，优先做小范围修复；如果需要回到前序阶段，写入 `reports/VERIFY_REPORT.md` 并标记为未通过。

## 输入

由模型先根据当前工作区判断项目布局，再把实际路径传给检查脚本。常见输入包括但不限于：

1. 论文入口文件：`main.typ`（Typst）或 `main.tex`（LaTeX）。
2. 正文章节目录或若干正文文件（`.typ` 或 `.tex`）。
3. 参考文献文件（`references.typ` 或 `references.tex`）。
4. 前序阶段的分析、建模、结果、图示报告。
5. 图表目录
6. 可复现代码目录。
7. 编译后的 PDF，或可由入口文件编译得到的输出 PDF。

不要假设论文目录一定叫 `paper/`，也不要假设结果文件一定在项目根。若项目使用不同命名，按实际结构传参并在 `reports/VERIFY_REPORT.md` 中说明。

## 工作流程


### Step 1: 运行文本质量门禁

按 [实际运行环境与路径](../_references/runtime_environment.md) 选定解释器，直接运行 `scripts/writing_check.py`，无须 Bash。路径由当前项目实际结构确定，变量先赋为已核对的路径。

```powershell
& $pythonExe $checkScript --paper-dir $paperDir --main $mainFile --root-dir $projectRoot
# 需要日志时可接 Tee-Object；用 $LASTEXITCODE 检查退出状态。
```

```bash
"$python_bin" "$check_script" --paper-dir "$paper_dir" --main "$main_file" --root-dir "$project_root"
```

完整参数见 `writing_check.py --help`，可显式传 `--sections-dir`、`--references`、`--figures-dir`、`--results-file`、`--problem-analysis`、`--all-results`。`writing_check.sh` 仅为 Bash 兼容入口，可通过 `PYTHON_BIN` 指定解释器。单文件论文不要求拆章节。

脚本只做有限静态扫描，不执行 TeX/Typst，不验证数学正确性。它会排除常见注释/代码示例并检查可解析的字面引用；动态路径、宏生成结构等必须由编译和实际输出核实。遇到 FAIL 先回查源码，确认真实缺陷再修复；解析器误判应修正检查器或记录该项限制，不能为迎合扫描器修改合法论文。未核实的疑点不自动记为通过。

PASS 仅代表静态覆盖范围未发现失败，仍须处理警告、独立核对数值与引用、编译及视觉检查。脚本中的指标/数字搜索只是线索，不是数值一致性证明。所选 Python 不可用则记脚本 NOT_RUN，可记录已完成的等价检查，但不宣称脚本已运行。

### Step 2: 章节数量和标题顺序

**Typst 引擎**检查：

- 核对实际章节与引用；`#include "..."`、`#include("...")` 或合法动态结构均可，不能仅凭一种语法计数。
- 章节顺序是否符合论文逻辑；文件名前缀只作线索，不构成强制排序。
- 正文是否按逻辑呈现必要标题；辅助源文件无需独立一级标题。
- 标题顺序是否符合所选论文类型。

**LaTeX 引擎**检查：

- 入口 `.tex` 文件中 `\input{...}` 或 `\include{...}` 的数量是否与实际正文结构匹配。
- 章节顺序是否符合论文逻辑；文件名前缀只作线索。
- 正文是否呈现适当标题；允许 `\section*{}`、宏生成标题及辅助文件，结合实际输出核对。

通用检查（两种引擎）：

- 章节文件是否缺失、重复引用、未被引用。
- 如果题目不是三问，不强行要求三段问题章节；按 `ANALYSIS_MODELING_REPORT.md` 的子问题数量核对。

### Step 3: 图表和章节匹配

**Typst 引擎**检查：

- 图表目录中的 PDF 是否在正文中被引用。
- `#figure(image(...), caption: [...])` 的图片是否真实存在。普通相对路径按 `.typ` 源文件解析，以 `/` 开头的路径按 Typst 项目根解析。
- 数据图是否放在对应结果/分析章节，非数据流程图是否放在方法/总体思路章节。

**LaTeX 引擎**检查：

- `\includegraphics{}` 引用的图片文件是否真实存在。按实际编译工作目录及 `\graphicspath` 解析，不能简单按章节文件所在目录判断。
- `\caption{}` 是否存在。
- 数据图是否放在对应结果/分析章节。

通用检查（两种引擎）：

- 连续图表之间是否有足够解释文字。
- caption 是否过长、过泛或与图意不一致。
- 图表编号、正文引用和章节语义是否一致。

不要生成 `*_typst_includes.typ` 或 `*_latex_includes.tex`；图表必须直接嵌在对应 section 中。

### Step 4: 写作质量和泄露检查

检查并修复：

- `TODO`、`PLACEHOLDER`、`待补充`、`待续写`、`示例数据` 等占位符。
- 论文正文出现内部工作流文件名、临时目录名、代码目录名或结果 JSON 路径。
- 过多列表式写作（Typst 中大量 `#list`、`enum`，LaTeX 中大量 `\begin{itemize}`、`\begin{enumerate}`）。
- 段落反复以"如图""由图""图 X 展示了"开头。
- 图表后没有解释、公式后没有变量含义、结论只报数不解释。

### Step 5: 数值和结果一致性

检查：

- 论文中的关键数值必须来自当前工作流声明的结果记录或结果 JSON。
- 目标函数值、误差指标、排名、权重、阈值、灵敏度结果不得与结果记录冲突。
- 如果存在汇总结果 JSON，抽取关键指标并确认论文正文中有对应结果。
- 按结果报告的关键指标表逐项核对指标身份、原始值、单位、百分数尺度和显示精度，并追溯生成脚本/数据文件。覆盖小于 1 的值、负数和科学计数法；数字“出现过”不构成一致证据。
- 本问用到的前问结果必须是有效批准版本；方案、结果、图表、论文不能混用不同运行版本。存在 `PENDING`、`REVISION_REQUESTED` 或 `STALE` 的必需审核时，不判定最终交付通过。
- 公式中的符号应在符号说明或正文首次出现处解释。

发现数值冲突时，不要自行发明新结果；应回到结果记录或代码输出修正论文。

仅能抽查时列出覆盖项和未查项，不把抽查当作全部通过。若需要修正已审核结果，先按共享变更规则标记后问与正文影响，重算并重新审核，不以改文稿掩盖源结果问题。

### Step 6: 引用和模板规范

按 [文献参与建模规则](../_references/literature_support.md) 核对文献报告、建模依据表及正文。检查题面给定、文献支持与自行提出三类依据是否区分，关键来源实际读取范围是否足以支持所述论断，公式/参数的单位、适用条件与本题改造是否对应。

捏造引用、引用实际不支持主张、把文献实验数值当本题结果，应判相关项 `FAIL`。必须核实的关键外部主张尚未核实时记 `NOT_RUN`，按总状态规则处理；明确标识且已有充分验证的自拟假设或原创改进，不因没有直接论文先例自动判失败。用户批准不能替代文献真实性核验。

检查：

- 参考文献文件是否存在，或模板是否采用了其他真实参考文献机制。
- 正文引用标记（Typst 的 `@label`/`#super`，LaTeX 的 `\cite{}`）是否能对应到真实参考文献。
- 中文论文 caption、表题、摘要语言保持中文；英文论文保持英文。
- 选定的模板入口是否保留所选比赛模板的必要封面、摘要、编号、页眉页脚或提交格式。
- 不要把模板结构误删成普通空白文档。


### Step 7: 编译

以下代码块为 Bash 示例；PowerShell 用已发现的绝对路径调用，例如 `& $xelatexExe -interaction=nonstopmode -halt-on-error $mainFile`，检查 `$LASTEXITCODE` 后再执行后续编译步骤；Typst 可用 `& $typstExe compile --root $projectRoot $mainFile $outputPdf`。编译器初始化、宏包和字体问题需如实记录，命令存在不等于可编译。

**Typst 编译**：

```bash
command -v typst >/dev/null 2>&1 && typst compile "$MAIN_FILE" "$OUTPUT_PDF"
```

**LaTeX 编译**：

```bash
command -v xelatex >/dev/null 2>&1 && xelatex -interaction=nonstopmode "$MAIN_FILE" && xelatex -interaction=nonstopmode "$MAIN_FILE"
```

LaTeX 从实际论文目录编译，按模板需要运行两遍及必要的 BibTeX/Biber 步骤；以实际引用是否解决为准。Typst 涉及论文目录外的图像时配置正确项目根。

编译失败必须修复语法、路径、图片引用或模板问题后重跑。编译通过后确认输出 PDF 非空。

### Step 8: PDF 视觉检查

如果模型有视觉能力，必须把编译后的 PDF 每页导出为 PNG 并逐页查看。这个步骤用于发现纯文本扫描和编译器无法发现的版式错误。

优先使用系统已有工具导出页面 PNG；不要为了视觉检查引入沉重依赖。可选命令示例：

```bash
mkdir -p _tmp/pdf-pages
if command -v pdftoppm >/dev/null 2>&1; then
  pdftoppm -png -r 160 "$OUTPUT_PDF" _tmp/pdf-pages/page
elif command -v mutool >/dev/null 2>&1; then
  mutool draw -r 160 -o _tmp/pdf-pages/page-%03d.png "$OUTPUT_PDF"
elif command -v magick >/dev/null 2>&1; then
  magick -density 160 "$OUTPUT_PDF" _tmp/pdf-pages/page-%03d.png
else
  echo "No PDF rasterizer found; record visual check as not run."
fi
```

导出后逐页检查：

- 页面是否空白、缺页、页数异常或页面尺寸异常。
- 标题、摘要、正文、页眉页脚、页码是否被裁切或位置明显错误。
- 表格是否超出页边距，单元格文字是否重叠、溢出、被截断。
- 图片、图题、表题、公式、编号是否与正文重叠。
- 公式是否越界，长公式是否压到页边距或下一段文字。
- 列表、段落、脚注、参考文献是否出现异常大空白、重叠或孤立残行。
- 中文/英文/数学符号字体是否明显缺字、乱码或 fallback 异常。
- 封面、摘要页、目录、附录等模板关键页面是否保留比赛要求的视觉结构。

如果是模板转换或已有参考 PDF 的项目，还应将不同引擎的 PDF 都逐页导出 PNG，按页对比版式差异；页数或页面尺寸不一致必须记录为硬错误或明确说明原因。

如果模型没有视觉能力，必须在 `reports/VERIFY_REPORT.md` 中明确写出“未执行视觉检查”的原因，并至少完成 PDF 非空、页数、页面尺寸等可程序化检查。

### Step 9: 写验收报告

创建 `reports/VERIFY_REPORT.md`：

```markdown
# 验证和验收报告

## 结论
PASS / FAIL / INCOMPLETE（注明本次验收范围）

## 检查项
| 检查项 | 结果 | 说明 |
| --- | --- | --- |

## 章节结构

## 图表引用

## 数值一致性

## 文本质量门禁

## 编译

## PDF 视觉检查

## 仍需处理的问题
```

检查项状态采用 `PASS`（已有通过证据）、`FAIL`（发现错误）、`NOT_RUN`（未执行）、`N/A`（不适用并说明原因）；轻微问题另列警告及处理情况。

总状态：必需项有失败为 `FAIL`；无失败但必需检查未做、必需审核未获批准或仍失效为 `INCOMPLETE`；本次范围内全部必需项通过才为 `PASS`。不能因为说明了无法编译或视觉检查的原因就判定最终论文通过。用户只要求源码检查时，可对该范围给结论，但不得扩展成 PDF 或提交就绪结论。

## 硬错误标准

以下问题必须判定 `FAIL`：

- 缺少选定的论文入口文件（`main.typ` 或 `main.tex`）或核心正文。
- 论文入口引用的章节文件不存在。
- 实际渲染的正文缺少必要章节或标题，且不符合所选模板/赛事要求；不能仅凭源文件没有某种字面命令判错。
- 章节顺序明显错误或重复。
- 正文仍有占位符。
- 正文泄露内部工作流文件名。
- 引用的图片不存在。
- 关键数值与结果记录冲突。
- 编译器可用但论文编译失败。
- 编译后的 PDF 为空、缺页、页数异常或页面尺寸异常且无法解释。
- 视觉检查发现正文、表格、图片、公式、页眉页脚、页码等关键元素重叠、裁切、越界或乱码。

## 警告标准

以下问题可判定为 `WARN`，但应尽量修复：

- 未引用的备用图片。
- 某章节过短或明显不均衡。
- caption 偏长。
- 参考文献偏少。
- 图表后解释文字不足。
- 视觉检查工具不可用时可报告限制，但最终 PDF 的视觉检查项仍为 `NOT_RUN`，基础元数据检查不能替代。
- 代码完整复现耗时过长时记录实际轻量检查范围；若完整复现属于本次必需项，该项仍为 `NOT_RUN`。
